# 方案三：部署到自己的服务器（长期稳定）

适合：真的要给几十个群友用几个月以上，希望数据在自己手里、访问稳定、随时能备份。

成本参考：腾讯云**中国香港**轻量应用服务器 2 核 2 GB（Ubuntu 24.04），约 25–35 元/月；域名约 50 元/年（可选，见下面的「没有域名怎么办」）。

> 不要选中国大陆地域的服务器，除非域名已做 ICP 备案。香港服务器按腾讯云说明不需要备案。

---

## 1. 准备服务器

1. 购买香港轻量服务器，系统选 **Ubuntu 24.04 LTS**，记下公网 IP 和 root 密码。
2. 在腾讯云控制台 → 轻量服务器 → **防火墙**，放通 `22`（SSH，仅自己用）、`80`、`443`。
3. 用 SSH 登录服务器（Windows 自带 `ssh root@你的IP`）。

## 2. 安装 Docker

```bash
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version
```

## 3. 放配置（不要把密钥写进代码）

```bash
mkdir -p /opt/runclub && cd /opt/runclub
# 把仓库里的 compose.ghcr.yaml、Caddyfile、config.env.example 传到这台机器
# 例如在本地执行：
#   scp compose.ghcr.yaml Caddyfile config.env.example root@你的IP:/opt/runclub/
cp config.env.example config.env
nano config.env
```

`config.env` 最少要改这几行：

```ini
RUNCLUB_DOMAIN=run.example.com          # 只写域名，不带 https://
PUBLIC_ORIGIN=https://run.example.com   # 完整地址，末尾没有斜杠
GROUP_CODE=你发给微信群的口令
ADMIN_SETUP_CODE=一长串随机字符
```

```bash
chmod 600 config.env    # 只有 root 能读
```

## 4. 用哪个 compose 文件

**方式 A（推荐）：直接拉 GitHub Actions 构建好的镜像** —— 服务器不用装 Node，更新快、内存占用低。

1. 把 `compose.ghcr.yaml` 第 7 行的 `ghcr.io/OWNER/runclub-monthly:latest` 改成你的仓库地址（全小写）。
2. 如果镜像包是 Public，直接启动；如果是 Private，先在服务器登录：

   ```bash
   echo 你的GitHub个人访问令牌 | docker login ghcr.io -u 你的GitHub用户名 --password-stdin
   ```

   （令牌在 GitHub → Settings → Developer settings → Personal access tokens，勾 `read:packages`。）

3. 启动：

   ```bash
   docker compose -f compose.ghcr.yaml pull app
   docker compose -f compose.ghcr.yaml up -d
   docker compose -f compose.ghcr.yaml ps
   ```

**方式 B：在服务器上直接构建**（没有用 GitHub Actions 时）

```bash
git clone https://github.com/你的用户名/runclub-monthly.git /opt/runclub-src
cp /opt/runclub/config.env /opt/runclub-src/config.env
cd /opt/runclub-src && docker compose up -d --build
```

首次构建 3–5 分钟。

## 5. HTTPS

Caddy 会自动申请 Let's Encrypt 证书，前提是**域名已经解析到这台服务器**：

1. 在域名 DNS 里加一条 `A` 记录：`run` → 服务器公网 IP。
2. 等待解析生效（`ping run.example.com` 返回你的 IP）。
3. `docker compose -f compose.ghcr.yaml logs -f caddy`，看到证书申请成功即可。

打开 `https://run.example.com`，按「管理员登录」创建负责人账号。

### 没有域名怎么办

三个选择，按推荐顺序：

1. **买个便宜域名**（最省心，几十元/年）。
2. 用免费动态 DNS 服务（如 DuckDNS、`IP.sslip.io`）拿到一个指向服务器 IP 的域名，填进 `RUNCLUB_DOMAIN`。这类域名偶尔会被 Let's Encrypt 限流或在大陆解析不稳定，属于将就能用。
3. 只用 `http://公网IP:3000` 开放端口访问 —— **不推荐**：没有 HTTPS，管理员 Cookie 和截图传输都是明文。

## 6. 以后更新代码

```bash
cd /opt/runclub
docker compose -f compose.ghcr.yaml pull app        # 拉最新镜像
docker compose -f compose.ghcr.yaml up -d           # 只重建变化的容器
docker image prune -f                               # 清理旧镜像
```

也可以在 GitHub 仓库的 **Actions → 部署到自己的服务器 → Run workflow** 一键完成（先在仓库 Settings → Secrets 里配好 `SSH_HOST`、`SSH_USER`、`SSH_KEY`、`DEPLOY_PATH=/opt/runclub`）。

## 7. 把上传的数据挪到服务器（从免费平台迁移）

1. 旧站点负责人登录 → 访问 `https://旧地址/api/admin/export` 保存 JSON（成绩清单，用于核对）。
2. 在新服务器上把旧平台的 `/data` 目录整包拷过来：

   ```bash
   # 在旧平台无法直接 scp 时，用一次性容器挂同一个卷打包
   docker compose -f compose.ghcr.yaml exec -T app tar czf - -C /data . > old-data.tar.gz
   ```

   把 `old-data.tar.gz` 传到新服务器后：

   ```bash
   cat old-data.tar.gz | docker compose -f compose.ghcr.yaml exec -T app tar xzf - -C /data
   docker compose -f compose.ghcr.yaml restart app
   ```

   注意：SQLite 的 `-wal` 文件要一起拷，先停容器再打包最稳。

## 8. 常用命令

```bash
docker compose -f compose.ghcr.yaml ps              # 状态
docker compose -f compose.ghcr.yaml logs -f app     # 应用日志
docker compose -f compose.ghcr.yaml logs -f caddy   # 证书/反代日志
curl -s http://127.0.0.1:3000/api/health            # 健康检查
```
